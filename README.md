# Hisense E-ink Auto Refresh（海信墨水屏自动刷新）

海信墨水屏设备的**强制全屏刷新**工具。监控前台应用内的触摸 / 按键操作次数，达到设定阈值后调用厂商 EPD 接口执行一次全局刷新，有效消除阅读时的墨水屏残影。

> 参考自 RefreshAi 项目；因原项目无中文且功能有限，故自行实现并补充了阅读界面自动识别、周期刷新、调试模式、**免设置授权（Shizuku / Root）** 等能力。

---

## 功能特性

- **操作计数刷新**：统计指定范围内的触摸 / 按键操作，累计达到「刷新间隔」后自动刷新一次。
- **监控范围可配**：
  - 监控所有应用（默认）
  - 仅监控指定应用（「配置监控应用」）
- **自动识别阅读界面**：开启后，切换界面延迟 1 秒读屏判定。阅读界面特征为「**正文文字 > 150 字，且 文字数 / 节点数 > 10**」（文字密集、节点稀疏），避免菜单、密集列表等非阅读界面误刷新。
- **忽略应用（白名单）**：部分付费阅读应用加密后无法读屏，可加入白名单，**直接视为阅读界面并跳过读屏**，优先级最高（即使是系统应用命中白名单也生效）。
- **系统应用自动跳过**：切换到的界面若是系统应用，默认不作为阅读界面、跳过读屏。
- **非阅读界面兜底重识别**：同一 activity 内多个 fragment 切换时无障碍事件不触发，故在非阅读界面累计操作 **5 次**后自动重新读屏识别，防止漏判。
- **周期刷新**：按固定时间间隔（秒）强制刷新一次，与操作计数相互独立。默认 300 秒（5 分钟），填 0 关闭。仅在非锁屏状态计时，锁屏暂停、解锁重置；若距上次刷新不足 30 秒则跳过，避免与操作触发刷新重复；触发成功后清零操作计数。
- **调试模式**：连续点击主界面标题 **10 次**开启（默认关闭）。开启后 XLog 输出线程信息 / 调用栈 / 边框，并将日志写入文件（`xlog/` 目录，按天归档、保留 7 天）；关闭后仅输出 Logcat、不写文件。
- **开机自启**：设备重启后自动拉起无障碍服务与监控。
- **应用级独立刷新参数**：在「监控应用列表」中，每个应用可单独配置「触发刷新次数」与「触发延迟」，覆盖全局默认值（默认 10 次 / 500ms），应用名后方配置按钮**默认禁用，勾选该应用后才可点击**。
- **免设置授权（Shizuku / Root）**：无需电脑 adb 即可完成关键授权：
  - **授权方案选择**：自动 / 只用 Root / 只用 Shizuku 三种方案，自动探测可用途径。
  - **独立授权按钮**：Shizuku、Root 各自独立授权按钮，仅在「可申请且尚未授权」时显示。
  - **一键开启无障碍**：在已授权的方案下，点「一键开启无障碍」自动拉起无障碍服务；已开启时提示「无障碍已开启」。Shizuku 方案下若 Shizuku 未启动，会提示「Shizuku 未启动，请先启动 Shizuku 并授权」。
  - **解除隐藏 API 限制**：已授权 Shizuku / Root 后，可直接点主界面标题栏右上角「解除隐藏API限制」按钮完成（执行 `settings put global hidden_api_policy 0`），无需连接电脑。
  - **保活加白**：一键将应用加入系统保活白名单，降低后台被杀概率。
  - **后台被杀免重点授权**：Root 授权状态持久化，应用后台被系统回收重启后自动恢复，无需重新授权。
  - **移除 1×1 悬浮窗**：不再依赖 `SYSTEM_ALERT_WINDOW` 悬浮窗监听触摸，普通应用即可正常授权。

## 工作原理

- 通过 **AccessibilityService**（`TYPE_WINDOW_STATE_CHANGED` + `TYPE_VIEW_CLICKED`）监听前台界面切换与用户操作。
- 界面切换时根据「白名单 → 系统应用 → 读屏判定」的优先级确定是否为阅读界面。
- 读屏判定遍历当前窗口节点，**只统计自身及所有祖先均可见的文本内容**（剔除被隐藏节点），并综合文字量与节点密度判定阅读界面。
- 周期刷新由 `Handler` 循环计时驱动，独立于操作计数。
- 刷新通过反射调用海信 `com.hmct.epd.EpdManager.forceClear()` 实现。
- 配置变更通过 `ACTION_CONFIG_CHANGE` 广播**热更新**，无需重启服务。
- **免设置授权**通过 **Shizuku**（以 adb 权限执行命令）或 **Root**（su）在应用内完成隐藏 API 解除与无障碍服务拉起，避免每次都连电脑。

## 权限与依赖

| 权限 / 组件 | 用途 |
| --- | --- |
| 无障碍服务（AccessibilityService） | 监听界面切换与操作事件（核心） |
| `REQUEST_IGNORE_BATTERY_OPTIMIZATIONS` | 防止后台被省电策略杀掉 |
| `RECEIVE_BOOT_COMPLETED` | 开机自启 |
| `QUERY_ALL_PACKAGES` | 枚举已安装应用（Android 11+ 包可见性） |
| `POST_NOTIFICATIONS` | 前台服务通知 |
| Shizuku（第三方应用） | 免 Root 以 adb 权限执行命令（可选，推荐） |
| Root 权限 | 以 su 执行命令（可选，与 Shizuku 二选一） |

> 注意：强制刷新依赖海信私有 EPD 接口 `com.hmct.epd.EpdManager`，非海信设备 / 不同系统版本可能不可用（会记录错误日志，不影响其他功能）。
> 旧版本所需的 `SYSTEM_ALERT_WINDOW`（悬浮窗）权限**已不再需要**——1×1 悬浮窗方案已移除。

## 使用步骤

1. **安装 ADB 驱动**：在电脑上安装 adb 工具（请自行搜索下载）。
2. **开启 USB 调试**：打开设备的「开发者选项 → USB 调试」，连接电脑并在弹窗中选择 **允许**。
3. **授权 Shizuku / Root（免设置授权）**：
   - 在主界面「免设置授权（Shizuku / Root）」区，先选择**授权方案**（自动 / 只用 Root / 只用 Shizuku）。
   - **Shizuku 方案**：在设备上安装并**启动 Shizuku**（Shizuku 自身需通过无线调试配对或 adb 激活）；启动后点「授权 Shizuku」完成授权。若 Shizuku 已安装但未启动，状态区「Shizuku 未授权」中的 *Shizuku* 一词可点击，直接跳转 Shizuku 应用；此时点「一键开启无障碍」会提示「Shizuku 未启动，请先启动 Shizuku 并授权」。
   - **Root 方案**：设备已 Root 时点「授权 Root」完成授权；后台被杀后重启应用会自动恢复，无需重新授权。
   - 若暂时未授权，也可临时用电脑执行 adb 命令兜底（见下）。
4. **解除隐藏 API 限制**（关键）：
   ```bash
   adb shell settings put global hidden_api_policy 0
   adb shell settings get global hidden_api_policy   # 输出 0 表示成功
   ```
   > 若已在第 3 步**授权 Shizuku / Root**，可直接点击主界面标题栏右上角「**解除隐藏API限制**」按钮完成，无需连接电脑执行 adb。
5. **开启无障碍**：在「服务状态」区点 **一键开启无障碍**，应用会自动拉起无障碍服务；若已开启会提示「无障碍已开启」。
6. **测试刷新**：在应用内点击 **测试刷新**，若墨水屏能正常触发一次全局刷新，说明接口访问正常，即可自由配置监控参数。

## 免设置授权（Shizuku / Root）详解

本工具的核心目标是**尽量不连电脑**也能完成授权与刷新。Shizuku 与 Root 都能让应用以高权限执行命令（解除隐藏 API、拉起无障碍服务），二者有其一即可。

- **授权方案选择**（位于提权区底部「一键开启无障碍」右侧）：「自动」会探测当前可用的授权途径（有 Root 优先用 Root，否则用 Shizuku）；「只用 Root」/「只用 Shizuku」可强制指定。切换方案后状态区会实时显示当前可用性与提示。
- **独立授权按钮**：Shizuku、Root 各自一个授权按钮，仅在「该途径可用且尚未授权」时显示，避免占用空间；已授权后按钮隐藏。
- **一键开启无障碍**：在已授权的方案下，点此按钮会尝试用 Shizuku / Root 拉起无障碍服务：
  - 无障碍已处于开启状态 → 提示「无障碍已开启」。
  - Shizuku 方案下 Shizuku 未启动 → 提示「Shizuku 未启动，请先启动 Shizuku 并授权」。
  - 没有任何可用授权（如 Root、Shizuku 均无）→ 提示「当前方案下无可用授权，请先授权或切换方案」。
- **状态区提示**：
  - Shizuku 方案下 Shizuku 已运行 → 「Shizuku 已授权」。
  - Shizuku 已安装但未启动 / 仅未授权 → 「Shizuku 未授权」（其中 *Shizuku* 一词可点击，跳转 Shizuku 应用引导启动并授权）。
  - 设备确实没装 Shizuku → 「未安装 Shizuku」。

## 调试模式（排查问题）

- **开启**：在主界面连续点击顶部标题文字 10 次，弹出「调试模式已开启」提示。
- **效果**：XLog 同时启用线程信息、调用栈、边框，并将日志写入 `Android/data/<包名>/files/xlog/`（按天归档、保留 7 天）。
- **关闭**：再次连点标题 10 次，日志停止写文件、恢复精简格式。
- 调试日志对定位「为何没刷新 / 为何识别为阅读界面 / 周期刷新计时」等问题非常有帮助。

---

## 注意事项

- 自动识别依赖读屏，仅对**可见文本**生效；加密、WebView、画布绘制等非标准文本界面可能识别失败，建议加入白名单。
- 系统应用、自身应用界面默认不参与读屏判定。
- 墨水屏刷新较慢，配置过低的刷新间隔可能带来明显闪烁，请按阅读习惯调整。
- 调试模式会落盘日志，长期开启可能占用少量存储空间（已限制保留 7 天）。
- 使用 Shizuku 方案时，请务必先在设备上**启动 Shizuku**（其自身需通过无线调试配对或 adb 激活），否则状态区会提示「Shizuku 未授权」且无法完成授权。

## 工程结构

- `EInkAccessibilityService.kt`：核心无障碍服务，负责界面监听、读屏判定、计数、周期刷新与刷新触发。
- `AppPreferences.kt`：SharedPreferences 配置封装（含周期刷新、调试模式、Root 授权状态等开关）。
- `activity/MainActivity.kt`：主配置界面（含调试模式连点入口、自定义标题栏、免设置授权与一键开启无障碍逻辑）。
- `util/PrivilegedShell.kt`：Shizuku / Root 授权探测与命令执行（含授权方案选择、隐藏 API 解除、`shizukuInstalled` 判定）。
- `activity/AppsActivity.kt`：应用选择列表（复用为「监控应用」与「忽略应用」两种模式，含自定义标题栏、返回按钮与每应用独立配置弹窗）。
- `view/AppListAdapter.kt`：应用列表适配器（DataBinding），含 `ListItem`（应用名 / 包名 / 图标 / 选中态 / 独立刷新参数 / 是否系统应用），负责配置按钮按勾选态启用与配置展示。
- `util/Utils.kt`：刷新接口、系统应用判断、应用枚举等工具。
- `util/NotificationUtils.kt` / `BootReceiver.kt` / `MyApp.kt`：通知、开机自启、XLog 初始化（按调试模式切换文件输出）。
- `util/DateFileNameGenerator.kt`：XLog 按日期归档文件名生成器。
